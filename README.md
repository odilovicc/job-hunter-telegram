Этот проект — персональный Telegram-юзербот, который автоматически ищет подходящие вакансии в выбранных вами каналах, оценивает их по вашим критериям и с помощью искусственного интеллекта (Google Gemini) генерирует идеальное сопроводительное письмо.

> [!NOTE]
> Если прям коротко, заходишь под свой аккаунт, в конфиге укажешь свой айди аккаунта от телеграм и токен бота, нажимаешь на старт ОБЯЗАТЕЛЬНО! Дальше просто настроишь конфиг, добавляешь каналы, добавить в папку своё резюме и всё. Запускаешь бота через ```deploy/job-hunter-telegram.service``` и всё, через ```sudo journalctl -u job-hunter-telegram.service -f``` смотришь логи. Дальше чилишь на кофейне на хуесосовом молоке, а бот тебе будет присылать текст вакансии, сопроводительное письмо и будешь решать стоит ли обратить внимание на компанию ООО НАЕБАЛОВО.
> Удачки в поисках работы <3

Бот работает в режиме **Human-in-the-loop (Человек в контуре)**: он не спамит всем подряд, а присылает вам в "Избранное" готовую вакансию с уже написанным письмом и кнопкой `[🚀 Отправить отклик]`. Вы контролируете процесс в один клик!

P.s: Бот был заточен исключительно для поиска работы в Узбекистане, примерный конфиг ```config.exmaple.yaml``` также содержит каналы которые публикуют вакансии только в Узбекистане. Если вы хотите использовать его для поиска работы в другой стране, вам нужно будет изменить конфиг. И еще я поменял `python3` на `python` чтобы бот работал на windows.

## ✨ Возможности

- 🔍 **Умный мониторинг:** Читает Telegram-каналы с вакансиями в реальном времени.
- 🎯 **Гибкая фильтрация:** Ищет по ключевым словам и отсеивает мусор с помощью стоп-слов.
- 📊 **Система скоринга:** Оценивает вакансии (грейд, формат, стек) и пропускает только те, что набирают проходной балл.
- 🤖 **Интеграция с Gemini AI:** Нейросеть пишет уникальные сопроводительные письма под каждую вакансию, учитывая ваше резюме.
- 🕹 **Управление в 1 клик:** Бот присылает готовый вариант в ваше "Избранное". Если нравится — жмете кнопку, и бот отправляет отклик рекрутеру.

---

## 🛠 Как это работает?

Бот пропускает каждое новое сообщение через **3 уровня фильтрации**:

1. **Уровень 1 (Быстрый фильтр):** Проверяет наличие обязательных слов (например, `Vue`, `Frontend`, `PHP`) и отсутствие стоп-слов (например, `Senior`, `React`, `Ментор`).
2. **Уровень 2 (Скоринг):** Алгоритм читает условия (график, формат, грейд, стек) и начисляет баллы. Вакансия проходит дальше, только если набирает минимальный проходной балл (по умолчанию 5).
3. **Уровень 3 (ИИ-Генерация):** Если вакансия идеальна, бот отправляет её текст в нейросеть Gemini, которая пишет короткое, вежливое и продающее сопроводительное письмо от вашего лица, упоминая прикрепленное резюме.

## 🚀 Быстрый старт

### 1. Клонирование репозитория
```bash
git clone https://github.com/yourusername/personal-tg-bot.git
cd personal-tg-bot
```

### 2. Установка зависимостей
Рекомендуется использовать виртуальное окружение:
```bash
python3 -m venv venv

# Активация для Mac/Linux
source venv/bin/activate
# Активация для Windows
venv\Scripts\activate

pip install -r requirements.txt
```

### 3. Получение API ключей

**Telegram (api_id и api_hash):**
- Перейдите на [my.telegram.org](https://my.telegram.org) и авторизуйтесь.
- Откройте раздел **API development tools**.
- Создайте новое приложение (название может быть любым).
- Скопируйте `api_id` и `api_hash`.

**Google Gemini (gemini_api_key):**
- Перейдите на [Google AI Studio](https://aistudio.google.com/app/apikey).
- Нажмите **Create API Key** и скопируйте его (бесплатно).

## 💻 Настройка конфигурации

1. Скопируйте пример конфига (если есть) или просто отредактируйте `config.yaml`.
2. В блоке `telegram` вставьте свои `api_id` и `api_hash`.
3. В списке `channels` укажите @юзернеймы или ссылки на каналы с вакансиями (без '@', например `vuejs_jobs`).
4. В блоке `ai` вставьте ваш `gemini_api_key`.
5. Поместите файл с вашим резюме в папку с проектом и назовите его `resume.pdf` (или укажите другой путь в `resume_path`).
6. Настройте блоки `include`, `exclude` и `rules` под свои навыки.
7. (Опционально) Если хостинг бота ограничивает прямой доступ к Telegram/Google
   (например, сервер в РФ), поставьте `network.mode: "cloudflare_worker"` —
   см. `cloudflare-worker/README.md` для деплоя релея.

## 🎮 Использование

Запустите бота командой:

```bash
python main.py
```

**При первом запуске:**
1. Введите ваш номер телефона в терминал (в формате `+998888888888`).
2. В Telegram придет код подтверждения (от официального аккаунта). Введите его в терминал.
3. Бот создаст файл сессии `bot_session.session` и больше не потребует авторизации.

**Процесс работы:**
Как только бот найдет подходящую вакансию, вы получите сообщение в **Избранном (Saved Messages)**:
- Текст вакансии
- Оценка алгоритма
- Готовое сопроводительное письмо
- Кнопка для быстрой отправки отклика рекрутеру

## Сопроводительные письма по ссылкам hh.uz

После обновления установите зависимости (`pip install -r requirements.txt`) и
перезапустите бот. В личном чате администратора появятся кнопки «✉️ Письмо для HH»
и «📄 Мой профиль»; их также можно вызвать через `/start`.

1. Вызовите `/resume`. Бот локально извлечёт факты из `user_profile.resume_path`
   (текстовый PDF, до 10 МБ / 30 страниц / 60 000 символов), покажет их и предложит
   подтвердить. Если извлечение некорректно, исправьте PDF и повторите команду.
2. Нажмите «Письмо для HH» или `/letter`, затем пришлите ссылку вида
   `https://hh.uz/vacancy/123456`. Можно отправлять следующие вакансии в этом же режиме.
   `/cancel` закрывает режим ввода, но не отменяет уже поставленные задачи.
3. Бот получает описание через официальный API HH, удаляет HTML и повторения,
   выбирает целые пункты требований и релевантные факты резюме, затем пишет письмо.
   Если HH недоступен или вакансия архивная, можно прислать её текст отдельным сообщением.
4. Готовое письмо приходит отдельным сообщением для копирования. Кнопки позволяют
   открыть вакансию, сократить письмо или получить другую формулировку.
   Отправлять отклик на HH нужно самостоятельно.

PDF и полная история диалога в Gemini не отправляются. Профиль — локально извлечённые
факты, без дополнительного ИИ-вызова на структуризацию. Профиль и письма сохраняются
в существующей SQLite-базе, уже исключённой из Git. Замена PDF требует нового подтверждения.
Отбор фактов использует совпадения терминов и алиасы, а не семантический поиск: перед
отправкой работодателю стоит проверить письмо, особенно при слабом совпадении стека.

Настройки `cover_letters` в `config.example.yaml` необязательны: работают значения
по умолчанию. `resume_chars`, `vacancy_chars`, `max_prompt_chars` — бюджеты **символов**,
не точное количество токенов. Непоместившиеся пункты исключаются целиком; бот сообщает
о сокращении длинной вакансии. Фактический расход Gemini, включая thinking-токены,
отображается в `/stats`. Укажите свой контакт в `cover_letters.hh_user_agent`.
Модель задаётся `ai.model`; без настройки сохраняется ранее использовавшаяся модель.
Лимит ответа ручных писем задаётся `cover_letters.max_output_tokens`.

Одна новая вакансия требует одного успешного вызова ИИ. При временных HTTP 429/5xx
возможны ещё две попытки с задержкой. Мониторинг и ручные письма используют общую
асинхронную очередь (`ai.min_interval_sec`, `ai.timeout_sec`). Это не отменяет квоты
провайдера. При ошибке ручного письма бот сохраняет задачу вместо выдачи шаблонной
заглушки: `/letters` показывает последние 10 ошибок и кнопки повтора, в том числе
после перезапуска. Повтор выполняется вручную, автоматического ожидания сброса
дневной квоты нет.

Готовые письма кешируются по содержимому вакансии, версии PDF, модели, версии
промпта и варианту письма. Повтор ссылки проверяет описание в HH, но при неизменных
данных не вызывает Gemini. Двойное нажатие одной кнопки варианта тоже использует кеш;
для следующей формулировки нажмите «Переписать» под новым вариантом.

Проверки без Telegram/Gemini и без доступа к рабочей базе:

```bash
python -m unittest discover -s tests -v
```

## Проверка пропущенных вакансий

Кнопка **«🔎 Скан истории»** или `/scan` открывает выбор периода: 1–7, 14 или
30 дней. Для другого периода используйте `/scan 10` (от 1 до 365 дней).
Период — последние N × 24 часа до момента запуска, а не календарные даты.
Бот проверяет все каналы из `telegram.channels` с обычными фильтрами и присылает
новые подходящие вакансии с письмами и кнопками отклика.

- `/scan_status` — текущий канал, число просмотренных сообщений, новых вакансий,
  повторов, отказов и ошибок. Прогресс также приходит во время обработки примерно
  раз в минуту и после завершения.
- `/scan_stop` — остановить после текущего сообщения или запроса истории.
- Одновременно работает один скан; кнопки и мониторинг новых сообщений продолжают работать.
- Уже обработанные ID пропускаются, включая отсеянные фильтрами сообщения. Повторный
  скан не переоценивает их после изменения фильтров. Ошибка доставки оставляет
  вакансию доступной для повторной обработки.
- Недоступный канал отмечается в итогах и не прерывает проверку остальных.
- После перезапуска незавершённый скан нужно запустить повторно. Обработанные ID
  сохраняются в SQLite, поэтому полный повтор периода безопасен при обычной работе.
  Как и прежде, авария строго между отправкой отчёта и записью ID в БД может дать дубль.

Режим запуска `--mode=yest` использует тот же механизм для вчера и сегодня
(с полуночи предыдущего дня UTC), не блокируя работу бота.

### Обновление резюме через Telegram

Нажмите «📄 Мой профиль» или вызовите `/resume`. Если PDF не найден или
не читается, бот покажет текущий путь и предложит настроить
`user_profile.resume_path` в `config.yaml` либо отправить PDF прямо в чат.
Путь считается от папки проекта, поддерживается `~`; после правки конфига
перезапустите бота. Без указанного пути используется `resume.pdf`.

Для обновления отправьте боту PDF документом в личном чате администратора.
Бот проверит текст (до 10 МБ, 30 страниц), сохранит файл в
`uploads/resume.pdf` и покажет профиль для подтверждения. Невалидный PDF
не заменяет предыдущее резюме. Загруженный файл имеет приоритет над конфигом,
используется для новых откликов и сохраняется после перезапуска. Чтобы снова
использовать путь из конфига, удалите `uploads/resume.pdf` и перезапустите бота.
